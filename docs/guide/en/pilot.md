# Pilot test of version 1.0

Version 1.0 is published when M&E practitioners who did not build it confirm that it can replace their usual files and agendas (section 11 of the specification). This chapter describes the pilot test.

## Participants

At least four M&E practitioners, including the project's reviewing pair: ideally an M&E officer of a national NGO, an M&E manager of an international NGO or consortium, a focal point of a partner organisation and an evaluation consultant. Each uses their own Windows computer.

## What each does

For three to four weeks, each participant runs **a complete test project**, preferably the copy of a real project they know (anonymised data), otherwise the example project.

| Week | Work | Expected result |
|---|---|---|
| 1 | Set up the project from its project document: sheet, calendar, places, partners, disaggregations, logframe, indicators, targets, monitoring plan, activities, budget | The project is described without another tool |
| 2 | Enter or import four quarters of data: entry, Excel form sent to a partner, Kobo or DHIS2 if available; check, validate, lock | The tracking table is identical to their usual Excel file, figure by figure |
| 3 | Keep the agenda and tasks for a real week; record feedback, recommendations, risks | The agenda replaces the usual one |
| 4 | Produce the quarterly report in their donor's format, with their organisation's Word template; produce the summary note of several projects | The report is sent as is or with layout touches only |

At the same time, three participants form a **team** (an administrator, an M&E officer, a partner focal point) and work for a week on one project, using at least two ways of exchanging (packages and shared folder, or server).

## What each records

For each week, in the feedback form of the test kit:

- what worked without help;
- each **blocker**: what prevented progress, the screen, the steps, a screenshot;
- each **figure that differs** from the usual file (a difference is a critical defect until proven otherwise);
- time spent, compared with usual practice;
- the answer to: "Can the tool replace your usual files and agendas for this work?" (yes, yes with reservations, no) and why.

## Success criteria

| Criterion | Threshold |
|---|---|
| Tracking figures matching the reference file | 100 % of indicators |
| Quarterly report produced in the donor's format | Every participant |
| "Yes" or "yes with reservations" to the replacement question | Every participant, reservations settled before publication |
| Blockers | All fixed, then checked by the person who reported them |
| Team work | Same figures in every copy at the end of the week, conflicts included |

## After the pilot

Each blocker becomes an issue. Fixes go into a working version, tested by the person who reported the blocker. When every criterion is met, the signing certificate is installed (see [Contributing](contributing.md)), version 1.0 is tagged and published.
